## 学习目标

理解 Meta 官方描述的 approval/audit trail 机制，在真实账户中建立可复核的权限登记和定期审查流程。

**Meta 官方依据：**[访问对应原始官方页面](https://ai.meta.com/muse/)。

**重要边界：**官方展示某项能力不等于当前国家、设备或账号已经开放；操作界面、授权按钮、套餐与可用性以你真实账号为准。本教程没有访问你的 Muse 账号，以下步骤是可复现的教学方案，不声称已经执行成功。

## 跟着做：6 步完成一次练习

1. **操作 1：**先查阅 Meta 官方产品介绍中关于一次性允许、始终允许、拒绝及活动轨迹的设计说明。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

2. **操作 2：**打开实际 Muse 账号的应用连接及权限管理界面，核对是否存在“始终允许”以及具体读写范围；不要根据截图猜按钮位置。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

3. **操作 3：**为每项已授权服务记录：连接器名称、授权日期、目的、操作范围、敏感数据类别、到期日。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

4. **操作 4：**进行只读任务并观察活动日志是否展示计划动作和已经完成的动作，逐一核对时间和外部状态。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

5. **操作 5：**凡涉及外发、支付、地址共享、账户设置，默认收紧为逐次审批；必要时直接撤销该连接器。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

6. **操作 6：**用测试账号验证撤销后不能继续读写已撤权系统。若结果不符合预期，保存脱敏证据并向官方报告。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

## 红队审核：容易踩的 4 个坑

1. 把用户提示词“禁止发送”当作系统权限的替代品。
2. 保留过宽的“始终允许”，忘记停止使用。
3. 看到 Agent 已回复“删除成功”就认为真实第三方授权已撤销。
4. 把完整操作日志、收件地址、浏览器 cookie 发到公开 Issue。

## 验收标准：必须留下证据

- [ ] 每项连接器授权都有可复核记录
- [ ] 高风险动作逐次获得明确审批
- [ ] 已撤销权限在外部系统也能检查，出现异常及时报告
- [ ] 完成时间与人工复核时间分开记录，并留下可以复现的输入摘要。
- [ ] 如未完成，明确记录失败原因、是否实际产生外部副作用和下次最小修复动作。
