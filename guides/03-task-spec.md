# 03｜六段式 Agent 任务书

> **学习目标：**把模糊提问转成可验收的交付合同。**更新核查：**2026-10-21。

[回首页](../index.html) · [官方与独立来源](../docs/SOURCES.md) · [安全基线](../docs/SECURITY.md)

**事实边界**：以下为独立整理的操作范式，不代表已经对你的 Muse 账号逐一实测。是否支持某功能以 Meta 官方当期说明和你的实际账号权限为准。

## 开始前确认

- Muse 指 Meta 2026 年推出的个人 AI Agent，不等于 Muse Code 或 Muse Wonder 开发者模型。
- 优先使用公开或脱敏样例。重要账号连接、对外发送或付款操作按最低权限、逐次核验原则处理。
- 记录「设备 / 地区 / 账号入口 / 时间」，避免将个别界面误写成所有人的固定流程。

## 操作步骤（每一步都能验收）

1. **步骤 1：**定义明确目标与完成条件，避免无限开放任务。
2. **步骤 2：**限定资料：公开网页、上传文件或指定连接器，注明时间范围。
3. **步骤 3：**写清结果表格字段、格式和交付时限。
4. **步骤 4：**设红线：不能发送、购买、删除、公开分享、授权新服务。
5. **步骤 5：**设检查点：先出计划、重要动作待审批、结束必须附核验证据。

## 一键复制的任务指令

```text
目标：【目标】。允许来源：【来源】。交付：【格式】。验收：【3条标准】。禁止任何外发、购买、删除、对外发布和权限变更。如需这些操作先申请单次批准。
【统一安全约束】不读取未授权私人信息；不要替我发消息、下单、支付、发布、删除、分享或更改权限。如确需外部动作，先列出具体内容、对象和风险，等待我在真实产品界面确认。
【交付格式】结果 / 来源 / 未证实项 / 待我审批的动作 / 下一步。
```

## 验收清单

- [ ] 拿到对应目标的实际交付物，能留档而非仅有口头“已完成”。
- [ ] 关键事实附一手链接、日期，错误或缺失明确标记。
- [ ] 需要写入第三方系统时，已经经过真实授权并复查外部系统状态。
- [ ] 记录总耗时、返工原因和下一次最小改进点。

## 对抗式质疑

**潜在失败：**口头写了“未经许可不得操作”，仍须核对应用层真实权限。

**反证问题：**如果任务结果看起来正确，哪一个关键事实或现实系统状态最有可能推翻它？找到反证前，保持结论为“待验证”。
