1. **操作 1：**从 Meta 官方 Fitness 页面了解官方介绍的运动计划、健康 App 连接和营养方案功能。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

2. **操作 2：**先使用虚构示例或你愿意提供的非敏感目标，明确训练频率、运动经验和可用时间。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

3. **操作 3：**生成一周运动安排与记录模板，而非声称“算法已观察到你的真实身体状态”。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

4. **操作 4：**医疗症状、伤病、用药或潜在风险应交由合适专业人员判断，不能依赖单个代理输出做诊断。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

5. **操作 5：**如果平台请求接入健康应用，逐项核实读取/写入范围和删除连接方式，原则上不用真实健康数据测试教程。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

6. **操作 6：**检查营养食材采购是否产生订单动作，购物结账必须单独确认，不接受自动购买。

## 红队审核：容易踩的 4 个坑

1. 用未授权健康 App 读取另一个家庭成员的数据。
2. 把训练建议当作医疗建议，忽略疼痛及身体限制。
3. 运动目标默认触发营养品购买和共享个人信息。
4. 把 Meta 官方的功能示例当成真实账户已开通的证据。
