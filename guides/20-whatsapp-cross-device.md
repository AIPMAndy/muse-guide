## 学习目标

在手机、桌面和 WhatsApp 的入口之间安全交接一个任务，明确哪些行为是官方描述、哪些已经在本账号复现。

**Meta 官方依据：**[访问对应原始官方页面](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)。

**重要边界：**官方展示某项能力不等于当前国家、设备或账号已经开放；操作界面、授权按钮、套餐与可用性以你真实账号为准。本教程没有访问你的 Muse 账号，以下步骤是可复现的教学方案，不声称已经执行成功。

## 跟着做：6 步完成一次练习

1. **操作 1：**在官方 Muse 产品页核对支持哪些客户端与聊天入口。Meta 在首发文章中介绍了 Muse App 和 WhatsApp 的对话方式。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

2. **操作 2：**使用个人可公开讨论、无需隐私数据的任务，如整理一段公开新闻；记录启动设备和任务唯一名称。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

3. **操作 3：**如果当前账号提供 WhatsApp 入口，从官方链接或真实应用界面发起，不接受陌生人发送的二维码或未知号码。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

4. **操作 4：**切换到另一设备后检查同一个任务的对话是否出现，不要因为名称相同就假设后台状态已经同步。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

5. **操作 5：**逐项核实：消息是否同步、原引用是否可打开、任务是否仍运行、是否需要重新授权连接器。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

6. **操作 6：**跨设备复制结果前删除个人姓名、详细位置、联系方式等私人信息；对外分享之前再次审批。
   - **必须记录：**日期 / 当前客户端与账号前提 / 实际动作 / 原始证据 / 是否完成。

## 红队审核：容易踩的 4 个坑

1. 把官方宣传支持 WhatsApp 当成所有手机号及地区已经可用。
2. 跨设备重复发送或购买，造成双重执行。
3. 向不明 WhatsApp 号码发送联系人列表或私人工作内容。
4. 只看聊天消息同步，不核查底层任务及外部系统结果。

## 验收标准：必须留下证据

- [ ] 记录两台设备、账号及版本前提
- [ ] 实现或明确标注未实现的任务接续
- [ ] 无重复外发、无第三方隐私资料被非必要共享
- [ ] 完成时间与人工复核时间分开记录，并留下可以复现的输入摘要。
- [ ] 如未完成，明确记录失败原因、是否实际产生外部副作用和下次最小修复动作。
